## 1. Проект Firebase

1. `console.firebase.google.com` → **Add project**. Имя — `Lumina Blocks`.
2. **Google Analytics включить при создании.** Потом включение возможно, но
   часть привязок (в том числе экспорт в BigQuery) проще сделать сразу.
3. Выбрать или создать аккаунт Google Analytics, регион — по аудитории.

Проект Firebase — это одновременно проект Google Cloud с тем же идентификатором;
сервисный аккаунт из раздела 6 создаётся именно в нём.

## 2. Регистрация Android-приложения

1. В проекте → **Add app → Android**.
2. **Android package name** — ровно та строка, что стоит в
   `apps/mobile/android/app/build.gradle` как `applicationId` и `namespace`.
   Опечатка здесь ломает и Crashlytics, и валидацию чеков.
3. Скачать **`google-services.json`**. По DEC-0015 этот файл **не коммитится**:
   он кладётся в CI секретом (раздел 8).
4. **Отпечатки SHA-1 и SHA-256 — нужны три набора, а не два.** Помимо
   отладочного ключа и ключа загрузки обязателен сертификат **Play App Signing**:
   Google переподписывает ваш APK своим ключом при доставке, поэтому установленное
   из магазина приложение предъявляет именно его отпечаток. Без него Google
   Sign-In (DEC-0018) сломается ровно там, где это дороже всего — в магазинной
   сборке, а не локально. Сертификат берётся в Play Console → Setup → App signing
   после первой загрузки артефакта. Замечание R7.

   Локальные отпечатки:

```bash
# отладочный ключ
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android -keypass android
# ключ загрузки (путь и алиас — из android/key.properties)
keytool -list -v -keystore <upload-keystore.jks> -alias <alias>
```

## 3. Генерация `firebase_options.dart`

```bash
dart pub global activate flutterfire_cli
cd apps/mobile
flutterfire configure --project=<firebase-project-id>
```

Команда создаёт `lib/firebase_options.dart`. Этот файл **коммитится** — он
содержит публичные идентификаторы клиента, а не секреты.

После этого `bootstrap.dart` должен передавать опции явно и перестать глотать
ошибку (пункт 1.4 блока DEC-0015):

```dart
await Firebase.initializeApp(
  options: DefaultFirebaseOptions.currentPlatform,
);
```

Провал инициализации больше не поглощается: он поднимает флаг готовности,
**пишется в независимый логгер** и в debug-сборке падает громко. Именно в
независимый: отправлять эту ошибку в Firebase Analytics или Crashlytics
бессмысленно — они и есть то, что не поднялось. В аналитику событие уходит
дополнительно и только если инициализация всё-таки удалась. Замечание R8.

## 5. Правила Firestore

Их в репозитории нет вообще (пункт 1.6 блока DEC-0015). Правила должны покрывать
**три** области, а не одну:

| Коллекция | Клиенту разрешено | Почему |
|---|---|---|
| `entitlements/{uid}` | только чтение своей записи | пишет `verifyPurchase` через Admin SDK, который правила обходит |
| `purchaseTokens/{token}` | ничего | защита от подмены привязки токена (DEC-0003) |
| `users/{uid}` — клиентский прогресс | чтение и запись своей записи, **с ограничением набора полей** | `CloudPlayerProgressRepository` пишет сюда с устройства; без ограничения полей клиент сможет записать себе что угодно, включая поля, которые сервер считает своими |

Про `users/{uid}` в первой редакции не было сказано — замечание R8.

Правила пишутся в `firestore.rules` в репозитории, проверяются emulator-тестами
на матрице deny/allow и разворачиваются через CLI:

```bash
firebase deploy --only firestore:rules
```

## 6. Cloud Functions и доступ к Play Developer API

1. **Перейти на тариф Blaze.** На Spark функция не сможет вызвать
   `androidpublisher` — исходящая сеть к сторонним API там закрыта.
2. В Google Cloud Console того же проекта включить **Google Play Android
   Developer API**.
3. Создать **сервисный аккаунт** в этом проекте.
4. **Назначить этот аккаунт исполнителем функции.** Это отдельный шаг, и без
   него всё остальное бесполезно: `functions/index.js:34` использует `GoogleAuth`
   с Application Default Credentials, то есть берёт **runtime service account**
   развёрнутой функции, а `onCall` на строке 38 задаёт только регион. Если не
   указать аккаунт явно, функция пойдёт под дефолтным compute-аккаунтом — и
   права, выданные в Play Console другому principal, не применятся: вызов Play
   API вернёт 403. Ожидание распространения прав этого не лечит.
   Задать через `runWith`/`serviceAccount` в определении функции либо при
   деплое, затем **проверить фактический principal в развёрнутой ревизии**.
   JSON-ключ для этого не нужен. Замечание R1.
5. В **Play Console → Users and permissions** пригласить **тот самый** аккаунт,
   который назначен исполнителем, и выдать права на просмотр финансовых данных
   и управление заказами — они нужны для `purchases.products.get`.
6. Развернуть функцию и задать имя пакета:

```bash
cd infra/cloud_functions
firebase deploy --only functions
```

`ANDROID_PACKAGE_NAME` должен совпадать с `applicationId` (DEC-0009). Сейчас в
`functions/index.js` дефолт другой — это и есть расхождение из пункта 1.3.

> Привязка сервисного аккаунта к Play Console обычно вступает в силу не
> мгновенно. Если первый вызов возвращает отказ по правам — это ожидаемо,
> повторите позже, прежде чем искать ошибку в коде.

## 7. Экспорт в BigQuery

Firebase → **Project settings → Integrations → BigQuery** → включить экспорт
Analytics и Crashlytics. Экспорт начинается с момента включения и задним числом
данные не переносит, поэтому включать надо **до** первого когортного окна, а не
после. Дальше поверх него строится дашборд по контракту
[10_DASHBOARD_MVP_CONTRACT.md](10_DASHBOARD_MVP_CONTRACT.md).

## 8. Секреты в CI

В GitHub → Settings → Secrets and variables → Actions:

| Секрет | Содержимое |
|---|---|
| `GOOGLE_SERVICES_JSON` | `google-services.json`, закодированный в base64 |

Получить значение:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('apps\mobilendroidpp\google-services.json'))
```

**Без этого секрета Android-сборка в CI не соберётся вообще.** Плагин
`com.google.gms.google-services` применяется безусловно, а сам файл исключён из
Git, поэтому на чистом runner его нет. Оба workflow теперь падают с внятным
сообщением, если секрет не задан, — раньше это выглядело бы как непонятная
ошибка Gradle. Замечание F2.
| `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS` | уже используются в `android-release.yml` |

В workflow файл раскодируется в `apps/mobile/android/app/google-services.json`
перед `flutter build`, ровно как это уже сделано для keystore.

**Никогда не коммитить:** keystore, JSON сервисного аккаунта, `google-services.json`,
любые `.env`. `firebase_options.dart` — коммитится, это не секрет.
